# Контракт регистрации

> **12.11.2026.** Код регистрации прежней версии (`registration.ts`, `RegistrationForm.svelte`) удалён. Текущая демо-форма (`src/lib/stroka/enroll.ts`) ничего не отправляет, HTTP-режима в ней нет. Контракт ниже сохранён как исторический материал для возможного будущего сервера; к текущему коду он не относится.

Это предложение для будущего сервера. В этой сборке HTTP выключен.

Флаг `HTTP_MODE_ENABLED` в `src/lib/registration.ts` равен `false`. Форма всегда вызывает `submitDemoRegistration` с `mode: 'mock'`. Функция `performHttpSubmission` экспортируется и покрыта тестом с подставленным `fetch`, но при выключенном флаге `fetch` не вызывается. Ответ `http_disabled` тоже не показывается в интерфейсе, потому что интерфейс не выбирает режим `http`.

Локальный успех и серверное сохранение различаются текстом. Локальный текст фиксирован: «Демонстрация: регистрация не отправлена».

## Повтор в mock и будущий retry

Память `submitDemoRegistration` запоминает и ошибки. Повтор таймаута с тем же ключом в mock возвращается сразу, без новых 700 мс. Это повтор уже показанного состояния, не доказательство, что транспорт восстановился. В форме для такого повтора написано: «Снова показан тот же демонстрационный ответ. Новая попытка не запускалась.» Фраза «не создаёт новую заявку» показывается только после локального успеха.

Пока идёт ожидание, поля можно менять. Смена персоны, пометки, подтверждения, закрытия или выбранного ответа отменяет незавершённую попытку: её результат не записывается в статус. Так ответ на экране относится к текущей попытке, а не к прежнему таймауту.

Перед включением HTTP нужно отдельно разрешить повтор после временного сбоя с тем же ключом и при этом не создавать вторую запись, если сервер уже вернул `accepted`. Таймаут или обрыв после POST означает «результат не подтверждён», а не «заявка точно не отправлена». Текст mock «Заявка не отправлена» в `performHttpSubmission` для timeout и network не используется.

## Запрос, когда сервер появится

`POST /api/demo/registrations`

Тело JSON, только эти поля:

```json
{
  "project_id": "d7",
  "scenario_id": "workshop",
  "preset_id": "demo-shelf",
  "idempotency_key": "ключ из 8–80 символов [A-Za-z0-9-]"
}
```

`preset_id` — `demo-shelf` или `demo-atelier`. Пометка до 120 символов в тело не входит.

Таймаут клиента по умолчанию 4000 мс.

## Ответ сохранения

HTTP 200 и JSON:

```json
{
  "submission_id": "id-из-8-80-символов",
  "status": "accepted"
}
```

`accepted` значит, что сервер сохранил демонстрационную заявку. Это не запись на мероприятие и не доставка во все каналы. Интерфейс так и пишет.

## Ошибка

Безопасные `code` и `message`. Код — 1–40 символов `[a-z0-9_]`. Сообщение — 1–200 символов без перевода строки, без `Error:` и без фрагмента `at `. Иначе клиент подставляет свой текст и не показывает stack trace и секреты.

Отдельные коды клиента: `timeout`, `network`, `bad_response`, `server_error`, `http_disabled`, `registration_closed`, `idempotency_conflict`.
